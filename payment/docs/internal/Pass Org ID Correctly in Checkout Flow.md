I will fix the stale data issue by ensuring the correct Organization ID is passed through the checkout flow.

**Root Cause:**
The `CheckoutPage` relies on `localStorage` to find the Organization ID. If the backend data was reset (or if `localStorage` holds an old ID), it tries to use an ID that no longer exists in the database, resulting in a 404 error. It fails to use the fresh ID generated by the Dashboard.

**Solution:**
I will update the navigation flow to explicitly pass the active Organization ID from the Dashboard to the Checkout Page.

1.  **Update `PricingModal.tsx`**: Pass the `orgId` prop to the `/checkout` route state when clicking Upgrade.
2.  **Update `CheckoutPage.tsx`**: Read the `orgId` from the route state instead of `localStorage`.

**Verification:**
This ensures that the checkout process always uses the active, valid session ID, eliminating the "Order Expired" error permanently.
