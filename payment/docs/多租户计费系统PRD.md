## 1. 产品概述

### 1.1 背景与愿景
本系统旨在构建一个灵活、可扩展的企业级多租户计费平台（SaaS Billing Platform）。它不仅处理基础的支付与发票，更作为连接业务价值与货币实现的纽带，支持订阅制、按量付费等多种商业模式，赋能SaaS服务商快速变现。

### 1.2 核心目标
*   **灵活计费**：支持从简单的固定订阅到复杂的阶梯式、用量式计费模型。
*   **多租户隔离**：确保数据安全与业务逻辑在租户间的严格隔离。
*   **自动化运营**：实现从订单、支付、发票到催收的全流程自动化。
*   **决策支持**：提供实时的财务指标（MRR/ARR）与用户行为分析。

## 2. 核心组件详解

### 2.1 用户与组织管理 (Identity & Tenant Management)

#### 2.1.1 多租户架构
*   **逻辑隔离**：所有核心数据表（如 Orders, Subscriptions, Usage）必须包含 `tenant_id` 字段。
*   **组织上下文**：用户登录后需选择或被默认分配到一个“当前组织”上下文，所有操作基于此上下文进行。
*   **邀请机制**：
    *   支持通过邮件链接邀请成员加入组织。
    *   支持设置链接有效期（如 48 小时）。
    *   支持一次性邀请链接。

#### 2.1.2 角色与权限 (RBAC)
基于角色的访问控制系统，细化权限颗粒度：

| 角色 (Role) | 描述 | 关键权限 |
| :--- | :--- | :--- |
| **Owner** (拥有者) | 组织创建者，拥有最高权限 | 删除组织、转让所有权、管理支付方式、所有Admin权限 |
| **Admin** (管理员) | 组织运营负责人 | 管理成员、修改订阅套餐、查看所有数据、配置Webhook |
| **Finance** (财务) | 专注财务处理 | 查看/下载发票、管理支付方式、查看计费报表，**无**业务数据操作权 |
| **Member** (成员) | 普通业务人员 | 使用核心SaaS功能、查看个人用量 |
| **Viewer** (只读) | 审计或监管人员 | 仅查看数据，不可进行任何修改操作 |

#### 2.1.3 企业认证 (KYC)
*   针对企业级客户，提供营业执照上传、税务信息（VAT/GST Number）登记入口。
*   认证状态影响发票类型（增值税专用发票 vs 普通发票）。

### 2.2 计费引擎 (Billing Engine)

#### 2.2.1 产品目录 (Product Catalog)
*   **Product (产品)**: 定义服务实体（如 "Cloud Storage", "API Access"）。
*   **Plan (计划/套餐)**: 产品的具体售卖方案（如 "Basic Monthly", "Pro Annual"）。
*   **Price (价格)**: 定义具体的收费规则。

#### 2.2.2 定价模型支持
1.  **固定订阅 (Flat Rate)**: 每月/每年固定金额（如 $99/月）。
2.  **席位制 (Per-Seat)**: 基础费 + (单价 * 用户数)。支持“购买时预付”或“按月结算”。
3.  **计量制 (Usage-Based / Metered)**:
    *   **Sum**: 累加模式（如发送邮件数）。
    *   **Max**: 峰值模式（如最大并发连接数）。
    *   **Last**: 终值模式（如月末存储量）。
4.  **混合模式**: 固定月费 + 超额用量费。

#### 2.2.3 计量服务 (Metering Service)
*   **幂等性设计**: 接收来自业务系统的用量事件（Event），通过 `idempotency_key` 防止重复计费。
*   **聚合周期**: 支持按小时、按天聚合用量数据，减少数据库压力。
*   **软/硬限制**: 
    *   *Soft Limit*: 达到 80% 用量发送邮件提醒。
    *   *Hard Limit*: 达到 100% 拒绝服务调用或触发自动升档。

#### 2.2.4 发票与税务
*   集成第三方税务服务（如 Stripe Tax / Avalara）自动计算税费。
*   支持生成 PDF 发票，并通过邮件发送给组织财务联系人。
*   支持 Credit Note（红冲发票）处理退款场景。

---

### 2.3 功能控制 (Feature Gating & Entitlements)

#### 2.3.1 权益映射 (Entitlements)
将订阅计划与具体的功能权限（Features）解耦，建立映射关系：
*   **Boolean Feature**: 是否拥有某功能（如 "SSO登录": true/false）。
*   **Numeric Feature**: 额度限制（如 "API调用次数": 10000次/月）。
*   **Static Feature**: 静态属性（如 "数据保留期": 30天）。

#### 2.3.2 权限检查 SDK
前端和后端需提供统一的检查方法：
*   `can(feature_key)`: 返回布尔值。
*   `getLimit(feature_key)`: 返回数值限额。

#### 2.3.3 升降级策略
*   **立即升级**: 用户支付差价，新权益立即生效。
*   **到期升级**: 当前周期结束后生效。
*   **降级**: 通常在当前周期结束后生效，需处理数据保留策略（如降级后超过存储限额的数据如何处理）。

### 2.4 业务流程 (Business Workflows)

#### 2.4.1 订阅生命周期
1.  **Active**: 正常付费状态。
2.  **Trialing**: 试用期，可配置是否需要信用卡。
3.  **Past Due**: 扣款失败，进入催收流程（Dunning）。
4.  **Unpaid**: 多次催收失败，服务部分受限。
5.  **Canceled**: 用户主动取消或因欠费被动取消。

#### 2.4.2 催收流程 (Dunning Management)
*   **T+0**: 扣款失败，发送邮件通知，保持服务。
*   **T+3**: 重试扣款，发送第二次警告。
*   **T+7**: 重试扣款，失败则锁定部分高级功能（降级服务）。
*   **T+14**: 最终重试，失败则标记为 Unpaid，完全停止服务。

#### 2.4.3 退款流程
*   **发起**: 用户或客服发起退款申请。
*   **审批**: 财务角色审批（小额可配置自动审批）。
*   **执行**: 调用支付网关退款接口。
*   **后续**: 触发 Subscription 更新（如立即终止或保留至期末）。

### 2.5 度量与优化 (Metrics & Analytics)

#### 2.5.1 关键财务指标
*   **MRR (Monthly Recurring Revenue)**: 月度经常性收入，SaaS 核心指标。
*   **ARR (Annual Recurring Revenue)**: 年度经常性收入。
*   **ARPU (Average Revenue Per User)**: 平均每用户收入。

#### 2.5.2 客户健康度
*   **Churn Rate (流失率)**: （流失客户数 / 总客户数）。
*   **LTV (Life Time Value)**: 客户终身价值。
*   **CAC (Customer Acquisition Cost)**: 获客成本（需录入市场投放数据）。

#### 2.5.3 系统指标
*   Webhook 投递成功率。
*   支付网关接口 P99 延迟。
*   用量统计数据的一致性校验报警。

## 3. 实施路线图 (Implementation Roadmap)

### Phase 1: MVP (基础计费闭环)
*   **目标**: 支持最基本的订阅售卖，跑通支付流程。
*   **功能**:
    *   组织/用户管理 (RBAC基础版)。
    *   集成 Stripe/Paddle 支付。
    *   支持固定月费/年费套餐。
    *   基础发票邮件发送。
    *   简单的功能开关 (Feature Gating)。

### Phase 2: Growth (用量与运营)
*   **目标**: 支持复杂的商业模式，提升运营效率。
*   **功能**:
    *   引入计量服务 (Metering Service)，支持按量付费。
    *   实现自动化的催收流程 (Dunning)。
    *   自助服务门户 (Customer Portal) 完善（换卡、查看历史账单）。
    *   初步的 MRR/Churn 报表仪表盘。

### Phase 3: Enterprise (企业级能力)
*   **目标**: 满足大客户需求，增强合规性与灵活性。
*   **功能**:
    *   支持多币种结算。
    *   合同制管理 (非标准定价，线下打款线上记账)。
    *   SSO 单点登录集成。
    *   详细的审计日志 (Audit Logs)。
    *   高级税务合规集成 (Tax Automation)。

---

## 4. 非功能性需求

*   **安全性**: 
    *   PCI-DSS 合规（不直接存储信用卡号，仅存 Token）。
    *   所有 API 通信强制 HTTPS。
    *   敏感操作（如删除组织）需二次验证 (MFA/Password confirm)。
*   **性能**:
    *   权限检查 API 响应时间 < 20ms。
    *   用量上报接口支持高并发（10k QPS+）。
*   **可用性**:
    *   核心计费服务 SLA 99.99%。
    *   支付网关故障时的降级处理（如暂存订单，稍后重试）。
