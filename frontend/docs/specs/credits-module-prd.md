## 1. 产品概述
### 1.1 背景
用户在使用 Deep Agent 平台时需要消耗“资源点”（积分）。为了让用户清晰地了解当前的资源状况、每日刷新规则，并提供便捷的升级通道，需要开发“积分详情卡片”及配套的“升级支付”流程。

### 1.2 目标
1.  **透明化**：清晰展示用户的积分构成（免费/付费）及刷新规则。
2.  **转化**：在积分详情入口提供醒目的“升级”引导，促进用户付费。
3.  **闭环**：打通从查看积分到支付升级的完整链路（本期为模拟支付）。

## 3. 功能需求

### 3.1 积分详情卡片 (UI)
**触发入口**：顶部导航栏（Header）右侧的“资源点”/“积分”显示区域。

**界面元素**：
1.  **当前等级标签**：
    *   显示用户当前等级，例如“免费”、“Pro”。
    *   字体加粗，显眼展示。
2.  **总积分展示**：
    *   图标：✨ (Sparkles icon)。
    *   标题：“积分”。
    *   数值：用户当前可用的总积分（免费+付费）。
    *   辅助信息：显示“免费积分”的具体数值。
    *   样式：数值右侧可能有箭头 `>`，暗示可点击查看详情。
3.  **每日刷新规则**：
    *   图标：📅 (Calendar icon)。
    *   标题：“每日刷新积分”。
    *   数值：每日赠送/刷新的额度（例如 300）。
    *   说明文案：“每天 00:00 刷新为 300”。
4.  **升级入口**：
    *   按钮文案：“升级”。
    *   样式：黑色背景，白色文字，圆角按钮（参考截图）。
    *   位置：卡片右上角或显眼位置。
5.  **底部链接**：
    *   文案：“查看使用情况 >”。
    *   交互：点击跳转（本期可先预留入口）。

**交互逻辑**：
*   **点击触发**：点击 Header 积分区域，卡片以 Popover 形式出现。
*   **关闭机制**：点击卡片外部区域自动关闭。

### 3.2 升级支付流程 (功能)
**触发**：用户点击卡片上的“升级”按钮。

**逻辑**：
1.  前端调用后端“创建订单”接口。
2.  后端返回模拟的支付信息（如 `order_id`）。
3.  前端显示“支付处理中...”状态（Loading）。
4.  前端调用“查询订单状态”接口（或模拟延时后直接成功）。
5.  支付成功后：
    *   弹出 Toast 提示“升级成功”。
    *   自动刷新当前的积分数据。
    *   关闭积分详情卡片。

## 4. 接口需求 (API Requirements)

### 4.1 查询用户积分详情
*   **Method**: `GET`
*   **URL**: `/api/user/credits`
*   **Response (JSON)**:
    ```json
    {
      "total_credits": 1037,
      "free_credits": 737,
      "daily_refresh_amount": 300,
      "daily_refresh_time": "00:00",
      "user_level": "Free" // or "Pro"
    }
    ```

### 4.2 创建升级订单
*   **Method**: `POST`
*   **URL**: `/api/payment/create-order`
*   **Body**:
    ```json
    {
      "plan_id": "pro_monthly" // 预留字段
    }
    ```
*   **Response**:
    ```json
    {
      "order_id": "ord_123456789",
      "status": "pending",
      "payment_url": "..." // 模拟时可为空
    }
    ```

### 4.3 查询订单状态
*   **Method**: `GET`
*   **URL**: `/api/payment/order-status`
*   **Query**: `order_id=ord_123456789`
*   **Response**:
    ```json
    {
      "order_id": "ord_123456789",
      "status": "success" // pending, success, failed
    }
    ```

## 6. 非功能需求
*   **响应速度**：积分查询接口响应时间 < 200ms。
*   **容错性**：支付接口失败时，前端应有友好提示，不应导致页面崩溃。
*   **安全性**：虽然是模拟支付，但前后端交互应遵循基本的认证鉴权流程（依赖现有 Auth）。
