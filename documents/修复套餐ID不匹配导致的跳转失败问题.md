# 套餐跳转功能修复方案

经过排查，当前"无法启动支付会话"的根本原因是前端 UI 传递的 `plan_id` 与后端数据库中定义的套餐 ID 不匹配。

## 问题诊断
1.  **报错分析**：后端日志显示 `404 Not Found`，表示请求的 `plan_id` 在数据库中不存在。
2.  **配置核对**：
    -   **后端配置** (`main.py`)：定义了三个套餐 `basic` ($20), `standard` ($40), `pro` ($200)。
    -   **前端配置** (`PricingModal.tsx`)：
        -   中间卡片 ($40) 错误地绑定了 ID `pro` (应该是 `standard`)。
        -   右侧卡片 ($200) 错误地绑定了 ID `plus` (应该是 `pro`)。

由于您点击的是 $200 的套餐（对应右侧卡片），前端发送了 `plus`，导致后端查无此套餐而报错。

## 修复计划
我们将修正 `PricingModal.tsx` 中的套餐 ID 映射，使其与后端完全一致：

1.  **中间卡片 ($40/月)**：将 `onSelectPlan('pro', ...)` 改为 `onSelectPlan('standard', ...)`。
2.  **右侧卡片 ($200/月)**：将 `onSelectPlan('plus', ...)` 改为 `onSelectPlan('pro', ...)`。

## 验证步骤
修复后，您可以执行以下操作进行验证：
1.  刷新 `/chat` 页面。
2.  点击"资源点" -> "升级"。
3.  点击 $200 套餐的"升级"按钮。
4.  预期结果：页面应正常跳转到 Mock 支付宝收银台，显示金额为 $200 (或 ¥1440)。
