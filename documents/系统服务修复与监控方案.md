# 系统服务诊断与修复方案

## 1. 故障诊断报告
经过详细排查，当前系统服务状态如下：

| 服务名称 | 端口 | 状态 | 影响 |
| :--- | :--- | :--- | :--- |
| **Agent 前端 (Chat)** | 3000 | 🔴 **不可用** | 用户无法访问 http://localhost:3000/chat |
| **Agent 后端 (API)** | 4000 | 🔴 **不可用** | Agent 相关功能无法使用 |
| **支付管理后台** | 5173 | 🟢 **正常** | 已恢复，运行正常 |
| **支付/积分后端** | 8001 | 🟢 **正常** | 运行正常，数据库连接正常 |

**根本原因分析：**
- Agent 平台的前端 (Next.js) 和后端 (NestJS) 服务进程未启动。
- 之前可能只关注了支付系统的开发 (5173/8001)，忽略了 Agent 宿主环境 (3000/4000) 的运行。

## 2. 修复实施计划

### 步骤 1: 环境配置检查
- 检查 `deep_agent0.1-main/backend` 是否存在 `.env` 配置文件，如缺失则基于 `.env.example` 创建。
- 确保端口 4000 和 3000 未被其他非相关进程占用。

### 步骤 2: 启动缺失服务
1. **启动 Agent 后端** (Port 4000):
   - 路径: `deep main html/deep_agent0.1-main/backend`
   - 命令: `npm run start` 或 `npm run start:dev`
2. **启动 Agent 前端** (Port 3000):
   - 路径: `deep main html/deep_agent0.1-main/frontend`
   - 命令: `npm run dev`

### 步骤 3: 验证集成连接
- 验证 http://localhost:3000/chat 页面加载情况。
- 验证积分同步功能：Agent 前端 (3000) -> 支付后端 (8001) 的数据获取是否正常。
- 验证 WebSocket 连接是否成功建立。

## 3. 监控与故障恢复机制
为防止类似问题再次发生，将建立以下机制：

1. **创建自动监控脚本 (`check_services.ps1`)**:
   - 定期检查所有关键端口 (3000, 4000, 5173, 8001) 的连通性。
   - 输出当前所有服务的运行状态报告。

2. **自动恢复策略**:
   - 在开发环境中，提供一键启动所有服务的脚本 `start_all_services.ps1`，确保所有依赖服务按正确顺序启动。
